The four pieces

Numbered because it is a real build order, not decoration — each one only makes sense once the one above it exists.

01

Orbit exporter orbit-export.rbSTART HERE

Pick the current selection or a component from a dropdown. Set azimuth step, elevation list, image width, output folder. It walks the camera round and writes a PNG at every stop.

The part that matters is fixed framing: camera distance is computed from the component's bounding box, not zoom_extents, so every image in a run shares an identical scale and centre. Parts stay comparable to each other and a spin doesn't wobble. Parallel projection optional, for the technical-illustration look.

Produces 72 transparent PNGs per part · housing_az045_el030.png · resumable, restores your camera
02

Exploded views explode.rb

Offsets sub-parts outward from the assembly centroid along their own axes by a factor you set, in one undoable operation. Feed the result to the exporter and you get exploded views from every angle — which is most of what an assembly manual's pictures actually are.

Produces the same 72 frames, exploded · reuses the tag structure already in the scripts
03

The manifest manifest.json

Every image tagged with its component, azimuth, elevation and assembly step. This is the piece that makes the manual dynamic rather than a folder of pictures: change a part, re-run the exporter, and the manual updates itself. Without it you are back to hand-placing images, which is what you have now.

Produces the contract between SketchUp and the manual — nothing downstream needs to know about SketchUp
04

The manual

Generated from the manifest. Each step shows its part; drag to rotate, exactly as above. Works offline, runs on a phone on a workbench, and needs no plugin. If it also has to print, the same manifest can drive a PDF — and I would reuse build-v2.js rather than write a second generator.

Produces the deliverable · rebuilt by re-running, never by hand

What I wouldn't build

  • A second PDF engine. build-v2.js already does branded page layout. If the manual needs printing, it drives it.
  • Live 3D in the browser. Pre-rendered frames look better, load faster, use SketchUp's own renderer, and can't break on a shop tablet.
  • The manual before the exporter. Look at real output first — the format decision is much easier with 72 actual images in a folder than in the abstract.

Two things I need from you

Which product?

WhisperRoom booths — 25 models, panels and seam seals — or the pendant line? Booths mean per-model variants and the catalog as a data source. Pendants are a much smaller, self-contained first target, and the parts already exist as scripts.

Did I read "dynamic" right?

I've taken it as drag-to-spin plus regenerated-from-data. If you meant something else — interactive step-throughs, per-configuration manuals, something linking back to a quote — say so now, because it changes what the manifest has to carry.
