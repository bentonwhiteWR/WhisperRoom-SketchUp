The panel, redesigned as a shop drawing

Same concept — one searchable panel of tools and toggles — redrawn so a new user can tell at a glance what runs once, what stays on in the model, and what each tool actually touches. Both frames below are interactive: search, flip toggles, open settings, star a tool, click a toolbar slot.

What changed, and why

Two kinds of thing, two visual grammars, one list. One row per script, in categories ordered the way a job actually runs (room → booth → dimensions → scenes → art → tidy-up, per the Researcher's tree). A script with an on/off carries a switch, an ON/OFF stamp and an orange edge-rail — it reads as state. Actions read as verbs: icon, name, and a RUN affordance on hover. No duplicate "abilities" list.

The state strip

The single biggest new-user confusion with stateful toggles is "what has this plugin already done to my model?" The strip under search answers it: one chip per ability that is on, click to jump to it. Orange = "this has drawn in your model" — the same orange as the dimension tags it draws.

The … convention, made visible

A trailing "…" meant "opens a dialog first" — invisible to anyone not told. It is now a small window glyph on the row, and tools with declared settings get an in-panel pre-run sheet (fields shown are illustrative).

Kept from the current panel

The single list + single search, the pasted-link command, the toolbar mirror with its honest "waiting on restart" state, rename-not-the-filename, and the bundled-copy notice. Those mechanisms are good; they were kept and re-clothed.

Dropped or hidden

Per-row "modified ago" timestamps and filenames (moved to tooltips), newest-first sorting (now a fixed pipeline order), the green ON colour (state is orange — one accent, one meaning), and eight dev/one-off scripts, moved behind the footer switch. Search still finds them — type probe — with a DEV badge.

Icon system

24-unit grid, 20-unit live area, 1.8 centred stroke, round caps and joins. Two inks only: graphite (currentColor) draws the context, brand orange #ee6216 draws exactly one thing — what the tool creates or changes. Three house motifs make an icon a WhisperRoom icon: the booth (solid rectangle with a door return), the room (open rectangle with a door swing), and the dimension string (line with oblique drafting ticks, never arrowheads). No icon is a bare abstraction — no gears, stars or wands stand alone.

Dimension the booth vs Measure the selection — the 20 px test: solid booth with a door vs a dashed selection box; the orange dimension string is common to both.

Art direction

One direction: the shop drawing. The panel borrows its language from the drawings this plugin exists to produce — hairline rules, drafting ticks, a single dimension-tag orange on quiet warm-grey surfaces, system type (Segoe UI), tabular numerals. It sits beside SketchUp's grey chrome as an instrument, not a web page. Rejected: the dark "pro DCC" look as the only mode (SketchUp ships light; dark is offered, not imposed), card grids (too wide, too soft for a 340 px working panel), and any second accent colour — orange keeps one meaning: this touches your model.

Orange is a verbAccent appears only on things that act on or exist in the model: active toggles, the RUN affordance, the state strip, the icon's subject. Never decorative.
340 px is the design widthEverything is one column; rows are two lines max; meta lives in tooltips. Widening the panel widens the blurbs, nothing reflows into columns.
State is never silentAn ability that is on shows four concurrent signals: rail, stamp, switch, chip. A toolbar change that waits on restart says so where it waits.
Both themes, same instrumentLight matches SketchUp's tray; dark lifts the orange one step (#f47b35) to hold contrast. All colour comes from the token sheet.
